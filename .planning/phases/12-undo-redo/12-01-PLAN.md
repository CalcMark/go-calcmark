<task type="auto">
  <name>Task 2: Implement UndoManager with circular buffer</name>
  <files>cmd/calcmark/tui/editor/undo.go</files>
  <action>
Add UndoManager struct:

1. Fields:
   - history []UndoBatch (circular buffer, pre-allocated to maxHistory)
   - head, size int (ring buffer pointers)
   - redoStack []UndoBatch (simple slice, grows/shrinks)
   - current []EditOperation (uncommitted operations)
   - maxHistory int (default 1000 per CONTEXT.md)

2. Constructor:
   - NewUndoManager(maxHistory int) *UndoManager
   - Pre-allocate history slice to maxHistory capacity

3. Methods:
   - AddOperation(op EditOperation): Add to current batch, clear redoStack (per CONTEXT.md discretion: standard behavior)
   - CommitBatch(): Move current operations to history as new UndoBatch with timestamp
   - Undo() (UndoBatch, bool): Pop from history, push to redoStack, return batch for reversal
   - Redo() (UndoBatch, bool): Pop from redoStack, push to history, return batch for re-application
   - HasUndo() bool, HasRedo() bool: Check availability
   - Clear(): Reset all state (for file open per CONTEXT.md: fresh start)

4. Circular buffer behavior:
   - When history is full, oldest batch is overwritten silently (per CONTEXT.md)
   - Pop returns most recent (LIFO from head)
   - Push advances head mod capacity

Memory budget (from CONTEXT.md): Max 2x file size. With 1000 states at ~1KB avg = ~1MB overhead, well within budget for 5MB files.
  </action>
