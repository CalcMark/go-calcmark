The root cause is that the left pane lines are not padded to a fixed width before the divider is added. Each line should be exactly `leftWidth` characters, creating a consistent column position for the divider.

**Step 1: Investigate current SideBySide implementation**

Read `cmd/calcmark/tui/editor/sidebyside.go` and identify where the left and right pane content is combined. The `Render()` function likely concatenates left content, a divider, and right content per line.

Currently, it probably does something like:
```go
output = leftContent + divider + rightContent
```

But it should ensure:
```go
output = padToWidth(leftContent, leftWidth) + divider + rightContent
```

**Step 2: Ensure left pane is padded to fixed width**

The fix should ensure every line of the left pane is exactly `leftWidth` characters. The `padLine` function in `sidebyside.go` should be used (or fixed if broken) to pad with spaces + background styling to fill the width.

Check these specific areas:
1. **sidebyside.go line ~50-80**: The Render() function that combines left and right content
2. **sidebyside.go line ~90-110**: The padLine helper that should pad to width
3. **view.go line ~800-850**: Where SideBySide is instantiated and used

The expected behavior:
- If leftWidth = 40, every left pane line should be exactly 40 visual characters (using lipgloss.Width)
- The divider then appears at column 40 on every line
- The right pane content starts at column 41 (or 42 if divider is multi-char)

**Step 3: Verify the fix approach**

Before implementing, verify:
- `lipgloss.Width(leftPaneLine)` should equal `leftWidth` for EVERY line
- The current code might be skipping padding for lines that are already "long enough"
- Ensure styled content (with ANSI codes) is measured correctly using `lipgloss.Width`, not `len()`

**Step 4: Implement the fix**

Modify `SideBySide.Render()` or `padLine()` to guarantee left pane lines are exactly `leftWidth`.

Pseudo-code for the fix:
```go
for each line:
    leftLine = leftContent[i]
    // CRITICAL: Pad left line to exact width
    paddedLeft = padLine(leftLine, leftWidth, leftBg)

        // Should never happen - but catch edge cases

    divider = "|"  // or whatever divider char
    rightLine = rightContent[i]

    output += paddedLeft + divider + rightLine
```

**Step 5: Handle edge cases**

- Empty lines: pad to full width
- Lines with ANSI styling: use lipgloss.Width for measurement
- Lines exceeding width: should already be wrapped by geometry.WrapText, but verify

```go
func TestDividerPositionConsistency(t *testing.T) {
    lipgloss.SetColorProfile(termenv.Ascii)

    // Create document with varying content lengths
    content := "# Header\nx = 10\nvery_long_variable_name = 100\ny = 5"
    doc, err := document.NewDocument(content)
    if err != nil {
        t.Fatalf("Failed to create document: %v", err)
    }

    m := New(doc)
    m.width = 80
    m.height = 24
    m.previewMode = PreviewFull

    // Get pane widths
    leftWidth, rightWidth := m.GetPaneWidths(80)

    // Expected divider column (at leftWidth position)
    expectedDividerCol := leftWidth

    // Render view
    view := m.View()
    lines := strings.Split(view, "\n")

    // Check each content line (skip status bar, headers, etc.)
    // Start from line with actual content (usually after header row)
    for i, line := range lines {
        if len(line) == 0 {
            continue // Skip empty lines
        }

        // Strip ANSI codes to find the divider position
        plainLine := stripANSI(line)

        // Find the divider character '|'
        dividerPos := -1
        for pos, ch := range plainLine {
            if ch == '|' {
                dividerPos = pos
                break
            }
        }

        if dividerPos == -1 {
            continue // This line doesn't have a divider (could be status bar)
        }

        // Verify divider is at expected column
        if dividerPos != expectedDividerCol {
            t.Errorf("Line %d: divider at column %d, expected column %d\n  Line: %q",
                i, dividerPos, expectedDividerCol, plainLine)
        }
    }
}

// stripANSI removes ANSI escape codes from a string for position checking
func stripANSI(s string) string {
    // Use existing stripANSI from view.go or implement here
    re := regexp.MustCompile(`\x1b\[[0-9;]*m`)
    return re.ReplaceAllString(s, "")
}
```

**Key points:**
- Test creates document with varying content lengths (short and long lines)
- Verifies every divider `|` appears at the same column position
- Uses stripANSI to measure plain text position (ignoring styling)
- Expected divider column = `leftWidth` (or `leftWidth - 1` depending on how padding works)
