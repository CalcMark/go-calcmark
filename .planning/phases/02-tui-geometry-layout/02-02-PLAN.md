**Step 2: Fix failures (if any exist)**
For each failing test, fix following this priority order and guidance:

1. **TestSC1 failure (side-by-side overlap):** The issue is likely in SideBySide.Render or View() line assembly. Check that every output line from View() has lipgloss.Width == totalWidth. If lines are wrong width, the padLine function in sidebyside.go may have an edge case. Fix in sidebyside.go. Do NOT change the overall View() structure.

2. **TestSC2 failure (source wraps bleeding):** The geometry.WrapText function should prevent this. If source content visually exceeds sourceContentWidth, check that linemodel wrapping in renderSourcePaneAligned uses the correct contentWidth (should be leftWidth - lineNumWidth - 2). Fix the width calculation if wrong.

3. **TestSC3 failure (result wraps pushing rows):** This would mean ComputeAlignedModel's alignment padding is wrong. When preview wraps to N lines and source is 1 line, source must get N-1 padding lines (AlignedLinePadding). Verify the max(numSourceVisualLines, numPreviewVisualLines) logic in aligned.go around line 320-325. Fix if needed.

4. **TestSC4 failure (asymmetric alignment):** Similar root cause to SC3. Verify that SourceToVisual mapping correctly points source line 1 to visual line 3 (not 1) when source line 0 wraps to 3 visual lines. Fix sourceToVisual map population if the first-visual-line logic is wrong.

5. **TestSC5 failure (resize reflow):** Check that tea.WindowSizeMsg handler (model.go ~line 282) properly updates m.width and m.height AND invalidates the aligned model cache. Verify the new View() uses the new dimensions. Fix cache invalidation if stale data persists.

**Step 3: If a test failure reveals a test issue (not a code issue):**
Fix the test in layout_success_criteria_test.go to match the actual correct behavior, and add a comment explaining why the test expectation was adjusted.
