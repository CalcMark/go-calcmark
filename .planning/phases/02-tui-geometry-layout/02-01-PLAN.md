  <name>Task 1: Create layout success criteria integration tests</name>
  <files>cmd/calcmark/tui/editor/layout_success_criteria_test.go</files>
  <action>
Create `cmd/calcmark/tui/editor/layout_success_criteria_test.go` with five tests, one per success criterion. Follow the existing test patterns in the codebase (see view_alignment_test.go for model setup). Use `lipgloss.SetColorProfile(termenv.Ascii)` in an init() for consistent output.

**Test 1: TestSC1_SourceAndResultsSideBySide**
- Create a document with `# Header\nx = 10\ny = 20\nz = x + y` (mixed text and calc blocks)
- Set model to width=80, height=24, previewMode=PreviewFull
- Call View() and split by "\n"
- Verify total line count does not exceed m.height (no overflow)
- Compute leftWidth, rightWidth via GetPaneWidths(80)
- For each line in the View output: verify lipgloss.Width(line) == leftWidth + rightWidth (when preview visible) -- this proves no overlapping/misalignment
- Call computeAlignedPanes and verify len(aligned.sourceLines) == len(aligned.previewLines) (1:1 alignment invariant)
- Verify Invariants().SourcePreviewMatch, MappingComplete, ReverseComplete all true

**Test 2: TestSC2_SourceWrapsAtColumnBoundary**
- Create a document with a very long calc line: `long_variable_name_total_sum = 100 + 200 + 300 + 400 + 500 + 600 + 700 + 800`
- Set width=80, height=24, previewMode=PreviewFull
- Compute leftWidth, rightWidth. Compute sourceContentWidth = leftWidth - 4 (line num) - 2 (gutter+space). This is the wrapping boundary.
- Call computeAlignedPanes and inspect aligned.sourceLines for that line. Count visual lines where sourceLineIdx == 0.
- Verify the count > 1 (line wraps). Verify each source line's Content has runewidth.StringWidth(content) <= sourceContentWidth.
- Verify no source visual line Content extends beyond sourceContentWidth (proves no bleed-through).
- Also verify via geometry.WrapText(longLine, sourceContentWidth) that wrap count matches aligned model's visual line count for that source line.

**Test 3: TestSC3_ResultWrapsIndependently**
- Create a document with a short source line that produces a long result: `x = 1` (source is short)
- Use a narrow previewWidth by setting totalWidth to something small like 60 and previewMode=PreviewFull (this makes the right pane ~27 chars)
- Mock test: instead, use ComputeAlignedModel directly with sourceContentWidth=40 and previewWidth=5 (very narrow, forces result wrapping)
- Set up input with a calc result where renderCalcLine returns a long string "x = 12345678901234567890" that wraps in 5-char width
- Verify the AlignedModel has totalVisualLines > 1 for that single source line (result wrapped)
- Verify source has padding lines (Kind == AlignedLinePadding) to match the extra result lines
- Verify len(SourceLines) == len(PreviewLines) (alignment maintained)
- Critically: if there are 2+ source lines, verify that source line 1's visual start position is AFTER all the wrapped result lines of source line 0 (no pushing down -- padding absorbs the difference)

**Test 4: TestSC4_AsymmetricWrappingVerticalAlignment**
- Create input where source line 0 wraps to 3 visual lines and result line 0 wraps to 1 visual line
- Use ComputeAlignedModel directly: sourceContentWidth=15, previewWidth=40
- Source line 0: "this is a text that will wrap to three visual lines easily" (wraps to 3+ at width 15)
- Result for line 0: "short" (1 visual line at width 40)
- Source line 1: "next line"
- Result for line 1: "next result"
- Verify: source line 0 occupies 3 visual lines (indices 0,1,2). Preview line 0 occupies 1 content line + 2 padding lines.
- Verify: SourceToVisual[0] == 0, SourceToVisual[1] == 3 (source line 1 starts at visual line 3, after all 3 visual lines of source line 0)
- Verify: at visual line 0, both source and preview show content for source line 0
- Verify: at visual line 3, both source and preview show content for source line 1
- This proves both start at the same vertical position with padding filling the gap.

**Test 5: TestSC5_ResizeReflowsCorrectly**
- Create a document with content that wraps differently at different widths
- Set model to width=120, height=40. Call View(), capture leftWidth1.
- Send tea.WindowSizeMsg{Width: 60, Height: 30} via Update()
- Call View() on the updated model. Capture leftWidth2.
- Verify leftWidth1 != leftWidth2 (dimensions changed)
- For the new View() output: verify every line is exactly 60 chars wide (lipgloss.Width)
- Verify line count does not exceed 30
- Call computeAlignedPanes with new widths. Verify alignment invariant still holds.
- Verify that wrapping changed: a line that was 1 visual line at width 120 may now be 2+ visual lines at width 60.

IMPORTANT: Use the `document.NewDocument(content)` constructor as seen in existing tests. Use `New(doc)` to create the editor model. Do NOT use `document.New()`. Follow the exact patterns in `view_alignment_test.go` and `aligned_test.go`.
