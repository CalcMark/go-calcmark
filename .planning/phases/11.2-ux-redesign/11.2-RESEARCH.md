# Phase 11.2: UX Redesign - Research

**Researched:** 2026-02-07
**Domain:** TUI command/help system UX, Go Bubble Tea framework
**Confidence:** HIGH

## Summary

This phase involves a holistic redesign of the CalcMark TUI editor's command and help system. The research focuses on implementing a command menu popup accessible via Ctrl+H, simplifying the status bar to show only essential hints (Ctrl+Q and Ctrl+H), and ensuring all accelerators work directly without requiring menu navigation.

The existing codebase already has a solid foundation for popup overlays (autocomplete popup), help overlays, and state management. The key insight is that the current implementation uses `InputState` to track which UI component receives input, and this pattern should be extended for the new command menu.

**Primary recommendation:** Implement the command menu as a new `StateCommandMenu` input state, using the existing popup overlay infrastructure from autocomplete, with navigation handled via the established `handleKey` pattern.

### Pattern 3: Accelerator-First Design
**What:** All commands have direct keyboard accelerators; menu is for discovery
**When to use:** Power-user focused TUI applications
**Example:**
```go
// Commands execute directly via accelerators
case tea.KeyCtrlS:
    m.saveFile("")
    return m, nil
case tea.KeyCtrlE:
    m.enterExportMode()
    return m, nil
// Menu is just for discovery, not required for action
```

### Pattern 4: Command Definition Struct
**What:** Define commands with name, accelerator, description, and action
**When to use:** Centralizing command definitions for menu and accelerators
**Example:**
```go
// In command_menu.go or model.go
type Command struct {
    Name        string      // "Save"
    Accelerator string      // "Ctrl+S"
    Description string      // "Save current file"
    Action      func(*Model) (tea.Model, tea.Cmd)
}

var EditorCommands = []Command{
    {"Save", "Ctrl+S", "Save current file", (*Model).saveFile},
    {"Export", "Ctrl+E", "Export to different format", (*Model).enterExportMode},
    {"Quit", "Ctrl+Q", "Quit editor", (*Model).handleQuit},
    // ...
}
```

### Anti-Patterns to Avoid
- **Slash commands for CalcMark:** The `/` character is the divide operator in CalcMark expressions. Never intercept it for command mode.
- **Modal vim-style modes:** This editor is modeless for editing. InputState is for UI context, NOT editing modes.
- **Hidden accelerators:** All accelerators must be discoverable via Ctrl+H menu.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Popup rendering | Custom string manipulation | `components.RenderPopupBox` pattern | ANSI escape codes, width handling, border rendering |
| Overlay compositing | String slicing | `overlayPopupOnLines()` / `overlayStringAt()` | ANSI code preservation, unicode width |
| Key binding help | Hardcoded strings | `shared.KeyMap` with Help() | Central source of truth, DRY |
| Popup positioning | Fixed coordinates | `geometry.CalculatePopupPosition()` | Screen edge clipping, above/below logic |

**Key insight:** The autocomplete popup already handles complex overlay rendering with ANSI codes, proper backgrounds, and edge clipping. Reuse this infrastructure.

## Common Pitfalls

### Pitfall 1: Breaking the "/" divide operator
**What goes wrong:** Attempting to use `/` for slash commands intercepts division in calculations
**Why it happens:** Many editors use `/` for command palette; CalcMark is a calculator
**How to avoid:** User decision locked - no slash commands. Ctrl+H is the command entry point.
**Warning signs:** Tests with expressions like `10 / 2` failing to evaluate

### Pitfall 2: Inconsistent accelerator handling
**What goes wrong:** Accelerators work in some states but not others
**Why it happens:** Key handlers in modal states swallow keys before reaching accelerators
**How to avoid:** Handle global accelerators (Ctrl+S, Ctrl+E, Ctrl+Q) before mode-specific handlers
**Warning signs:** Save not working when autocomplete popup is visible

### Pitfall 3: Status bar clutter
**What goes wrong:** Status bar becomes unreadable with too many hints
**Why it happens:** Adding hints incrementally without considering overall UX
**How to avoid:** User decision: Status bar shows ONLY "Ctrl+Q quit | Ctrl+H help/commands"
**Warning signs:** Hints wrapping or being truncated

### Pitfall 4: Help overlay vs command menu confusion
**What goes wrong:** Two overlapping concepts (help and commands) with unclear distinction
**Why it happens:** Ctrl+H traditionally opens "help" but user wants "command menu"
**How to avoid:** Ctrl+H opens command menu which INCLUDES help as one option
**Warning signs:** User unsure where to find information

### Pitfall 5: Background color bleeding through popup
**What goes wrong:** Terminal default background shows around popup edges
**Why it happens:** lipgloss strips trailing spaces, ANSI codes not properly terminated
**How to avoid:** Use `ensureFullWidth()` pattern, explicit ANSI reset after overlay
**Warning signs:** Gray or colored gaps around popup borders

### Command Menu Popup Rendering
```go
// Source: cmd/calcmark/tui/components/suggest.go - RenderPopupBox pattern
func RenderCommandMenuPopup(commands []Command, selected int, width int, style PopupStyle) string {
    innerWidth := max(30, width-2)

    borderFg := style.Border.GetForeground()
    borderStyle := lipgloss.NewStyle().Foreground(borderFg)

    topBorder := borderStyle.Render("╭" + strings.Repeat("─", innerWidth) + "╮")
    bottomBorder := borderStyle.Render("╰" + strings.Repeat("─", innerWidth) + "╯")
    leftBorder := borderStyle.Render("│")
    rightBorder := borderStyle.Render("│")

    var lines []string
    lines = append(lines, topBorder)

    // Title row
    title := " Commands"
    for len(title) < innerWidth { title += " " }
    titleStyle := lipgloss.NewStyle().Bold(true).Background(style.Item.GetBackground())
    lines = append(lines, leftBorder + titleStyle.Render(title) + rightBorder)

    // Command items
    for i, cmd := range commands {
        line := fmt.Sprintf(" %-12s %s", cmd.Accelerator, cmd.Name)
        for len(line) < innerWidth { line += " " }

        var styledLine string
        if i == selected {
            styledLine = style.Selected.Render(line)
        } else {
            styledLine = style.Item.Render(line)
        }
        lines = append(lines, leftBorder + styledLine + rightBorder)
    }

    lines = append(lines, bottomBorder)
    return strings.Join(lines, "\n")
}
```

## Open Questions

Things that couldn't be fully resolved:

1. **Command menu layout**
   - What we know: Should list all commands with accelerators
   - What's unclear: Should it be scrollable? How many items? Categories?
   - Recommendation: Start simple - single flat list, add categories if needed

2. **F1 key handling**
   - What we know: Currently F1 also triggers help (same as Ctrl+H)
   - What's unclear: Should F1 continue to work? Should it open different help?
   - Recommendation: Keep F1 as alias for Ctrl+H (command menu)

3. **Help content in command menu**
   - What we know: User wants comprehensive command reference
   - What's unclear: Inline in menu vs separate overlay when selected
   - Recommendation: Show description inline; full help as separate panel selection
