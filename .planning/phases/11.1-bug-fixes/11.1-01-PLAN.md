  <files>cmd/calcmark/tui/editor/model.go</files>
  <action>
The bug is in handleDeleteKey() at line ~850. The issue is that transitionToEditing() must be called BEFORE modifying editBuf because:
1. If editBuf is empty, transitionToEditing() reloads it from the document
2. If we delete first then transition, the reload undoes the deletion

Current code should already have transitionToEditing() first, so investigate:
1. Is debounce timer resetting editBuf after deletion?
2. Is transitionToProcessing clearing editBuf before DELETE is processed?
3. Is there a state where editBuf is empty but cursor is positioned on content?

Fix approach:
- Ensure handleDeleteKey() calls transitionToEditing() unconditionally at the top
- Add debug logging if needed to trace editBuf state transitions
- The fix should be minimal - likely ensuring proper ordering of operations

After fix, run the existing delete_single_char_test.go tests:
