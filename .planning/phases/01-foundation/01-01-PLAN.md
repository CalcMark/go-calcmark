  There are 3 pre-existing test failures that block `task test` from passing:

  **Failure 1 and 2: TestViewportDoesNotExceedHeight and TestViewportHeightWithLargeContent**
  The View() function renders 25 lines for a terminal height of 24. This is an off-by-one in the content height calculation in `view.go`.

  Looking at the View() function:
  - `contentHeight = totalHeight - 5` (reserves 5 lines: status bar 2 + context footer 2 + separator 1)
  - But the actual rendered output includes: source header (1) + content + empty line (1) + context footer (variable) + separator (1) + status bar (2 lines)

  The issue is that the rendering produces one more line than allocated. Investigate the exact source of the extra line by counting rendered elements:
  - Source header: 1 line
  - Globals padding (when preview visible): globalsHeight lines
  - Source content: sourceContentHeight lines
  - Empty line: 1 line
  - Context footer: 2 lines typically
  - Separator: 1 line
  - Status bar: 2 lines

  The fix: Adjust `contentHeight` calculation. Currently `totalHeight - 5` but the actual overhead is 6 lines (header=1, empty=1, separator=1, status=2, context footer has at least 1 line but the footer is 2 lines). Change the subtraction to account for the correct number of overhead lines. The test output shows the View renders:
  - Line 1: "Source" header + "Preview" header
  - Lines 2-3: globals padding (2 lines)
  - Lines 4-20: content (17 lines)
  - Lines 21-23: empty + context footer area (3 lines)
  - Line 24: separator
  - Lines 25-26: status bar (2 lines) -- but this is 26 lines, 25 after the trailing line

  The exact fix: Change `contentHeight := totalHeight - 5` to `contentHeight := totalHeight - 6` in the View() function. This accounts for the actual overhead correctly.

  IMPORTANT: After making the fix, verify both viewport tests pass. If changing to `-6` overcorrects (renders 23 lines), try `-5` with adjusting `paneContentHeight` instead. The goal is exactly `m.height` lines of output.
