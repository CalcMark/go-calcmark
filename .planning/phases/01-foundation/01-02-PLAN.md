  ```go
  // It handles text wrapping with unicode-aware width calculation and computes

  ```

  **2. `geometry.go`** -- Port WrapText from `cmd/calcmark/tui/editor/linemodel.go` (lines 238-300):
  - Copy the WrapText function exactly, but replace ALL `lipgloss.Width(...)` calls with `runewidth.StringWidth(...)`.
  - The function signature stays the same: `func WrapText(text string, maxWidth int) []string`
  - Import `github.com/mattn/go-runewidth` (direct dependency added in Plan 01).
  - Do NOT import `lipgloss` or any charmbracelet package.

  Also implement `CalculateRowGeometry` based on the code.sh algorithm (research document lines 103-132):
  ```go
  type RowGeometry struct {
      Height     int      // Number of visual lines needed (max of left, right)
      LeftLines  []string // Left column visual lines (padded to Height with empty strings)
      RightLines []string // Right column visual lines (padded to Height with empty strings)
  }

  func CalculateRowGeometry(srcLine, resultContent string, leftWidth, rightWidth int) RowGeometry
  ```
  The function:
  - Wraps srcLine using WrapText with leftWidth
  - Wraps resultContent using WrapText with rightWidth (skip if empty string)
  - Height = max(len(leftWrapped), len(rightWrapped)), minimum 1
  - Pads the shorter side with empty strings to match Height

  Also add a `StringWidth` convenience function that wraps `runewidth.StringWidth` so callers don't need to import runewidth directly:
  ```go
  func StringWidth(s string) int {
      return runewidth.StringWidth(s)
  }
  ```

  **CRITICAL CONSTRAINTS:**
  - Only import: `github.com/mattn/go-runewidth` and standard library.
  - ZERO imports from `charmbracelet/*`, `lipgloss`, `bubbletea`, or `bubbles`.
  - ZERO imports from `cmd/calcmark/tui/editor` (prevent circular dependency).
  - The WrapText port must produce IDENTICAL output to the editor version for all inputs (same word-boundary wrapping logic, same hard-break fallback, same empty string handling).

  **3. `geometry_test.go`** -- Comprehensive table-driven tests:

  Test WrapText with these cases (at minimum):
  - Empty string -> `[""]`
  - String shorter than maxWidth -> single element unchanged
  - String exactly maxWidth -> single element unchanged
  - String with word boundaries that wraps at word boundary
  - String without spaces that hard-breaks
  - Single character wider than maxWidth (CJK/emoji edge case)
  - maxWidth <= 0 -> returns original text
  - Unicode text (multi-byte characters)

  Test CalculateRowGeometry with these cases (at minimum):
  - Single line both sides (no wrapping needed)
  - Left wraps, right does not (left longer)
  - Right wraps, left does not (right longer)
  - Both wrap asymmetrically (different wrap heights)
  - Empty result (resultContent = "")
  - Both empty (srcLine = "", resultContent = "")
  - Very narrow widths (5 chars) with long text (stress test)
  - Zero width edge case

  Test StringWidth:
  - ASCII text
  - CJK characters (double-width)
  - Empty string

  Run: `go test ./cmd/calcmark/tui/geometry/... -v` to verify all tests pass.

  Also verify zero TUI dependencies:
