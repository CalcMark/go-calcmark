<feature>
  <name>Type-Preserving Napkin Conversion</name>
  <files>impl/interpreter/napkin_eval.go, impl/interpreter/napkin_eval_test.go</files>
  <behavior>
    Napkin conversion rounds a value to 2 significant figures while preserving the input type:

    - *types.Quantity input  -> *types.Quantity output (same unit, rounded value)
    - *types.Currency input  -> *types.Currency output (same symbol, rounded value)
    - *types.Rate input      -> *types.Rate output (same amount unit and per-unit, rounded value)
    - *types.Duration input  -> *types.Duration output (same unit, rounded value)
    - *types.Number input    -> *types.Number output (rounded value)

    Test cases:
    - `accumulate(5 MB/s, 1 day) as napkin` -> Quantity ~400 GB (not Number 430000)
    - `$1234567 as napkin` -> Currency ~$1.2M (not Number 1200000)
    - `100 MB/s as napkin` -> Rate ~100 MB/s (type preserved)
    - `86400 seconds as napkin` -> Duration ~86000 seconds (or auto-normalize to ~1 day)
    - `1234567 as napkin` -> Number ~1.2M

    Auto-normalization for quantities:
    - 422000 MB -> ~400 GB (find human-friendly unit scale)
    - Use 1000 threshold: when value > 1000, scale up to next unit prefix
  </behavior>
  <implementation>
    1. In evalNapkinConversion, after rounding the numeric value:
    2. Based on input type, reconstruct the SAME type with rounded value
    3. For Quantity: also auto-normalize to human-friendly unit if value > 1000
    4. For Currency: preserve symbol, round value
    5. For Rate: preserve both Amount.Unit and PerUnit, round Amount.Value
    6. For Duration: preserve unit, round value (optionally normalize)
    7. For Number: return rounded Number (existing behavior)

    Key fix location: Lines 24-40 and 99 of napkin_eval.go
    Current bug: Line 99 returns types.NewNumber() regardless of input type
    Fix: Replace with type-aware return that reconstructs original type
  </implementation>
</feature>
