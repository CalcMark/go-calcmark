Audit pattern to look for (THE BUG PATTERN):

1. Check if it handles all relevant types
2. Check if return type matches input type
3. Document any findings

<task type="auto">
  <name>Task 2: Fix any discovered type erasure bugs</name>
  <files>impl/interpreter/operators.go, impl/interpreter/unit_conversion_eval.go, impl/interpreter/functions.go</files>
  <action>
For each type erasure issue found in Task 1:

1. Apply the same fix pattern used for napkin:
   - Instead of returning types.NewNumber(), reconstruct the original type
   - Use a switch that returns the same type as input

2. Common fix pattern:
```go
// BEFORE (bug)
return types.NewNumber(result)

// AFTER (fixed)
switch v := original.(type) {
case *types.Quantity:
    return &types.Quantity{Value: result, Unit: v.Unit}
case *types.Currency:
    return &types.Currency{Value: result, Symbol: v.Symbol}
// etc.
}
```

3. If no bugs found, document that audit passed

Note: evalAverage and evalSqrt intentionally return Number because they aggregate multiple values - this is correct behavior for math functions. Only flag type erasure for operations that should preserve type.
  </action>

  </verify>
