# CalcMark-to-Hugo Full Document Rendering Pipeline

**Date:** 2026-03-10
**Status:** Ready for planning

## What We're Building

A build-time pipeline that converts `.cm` example files into fully evaluated Hugo pages, so each worked example on calcmark.org links to a rendered "full document" view showing the complete CalcMark file with computed results inline.

### User-Facing Behavior

1. Each worked example page (e.g. `/docs/examples/services-pl/`) gets a prominent **"View full document"** link near the top of the page.
2. That link goes to a child page at `/docs/examples/services-pl/full/` which shows the entire `.cm` file evaluated via `cm convert --to md` and rendered as a standard Hugo page.
3. The full-document pages do **not** appear in the sidebar navigation -- only reachable via their parent example page.

## Why This Approach

- **Extend `doceval`**: The existing `cmd/doceval` already handles all calcmark-to-site transforms. Adding `.cm` file conversion here keeps the pipeline unified -- one tool, one `task generate-docs` step, one place to debug.
- **Frontmatter `calcmark_source` field**: Each example page explicitly declares its backing `.cm` file (e.g. `calcmark_source: testdata/examples/services-pl.cm`). Explicit over convention-based matching -- no filename coupling, easy to audit.
- **Evaluated output as plain markdown**: `cm convert --to md` produces markdown with results inline. Wrapping it with Hugo frontmatter and writing it as a regular `.md` page means zero custom layout work -- it renders with the standard site theme.
- **Nested URL `/full/`**: The full-doc is a child of the walkthrough page. Clean hierarchy, natural discovery.

## Key Decisions

1. **Pipeline**: Extend `cmd/doceval` with a new phase that processes `calcmark_source` references.
2. **Hugo archetype**: A `worked-example` archetype (`site/archetypes/worked-example.md`) enforces required structure for all example pages. Running `hugo new --kind worked-example docs/examples/<name>.md` scaffolds the page with all required frontmatter fields and body skeleton. This is the single source of truth for what a worked example page must contain.
3. **Frontmatter**: The archetype requires `calcmark_source: <path>` (repo-relative path to the `.cm` file), along with `title`, `summary`, `weight`, `calcmark_build: progressive`. Missing `calcmark_source` means doceval skips full-doc generation for that page.
4. **Output format**: `cm convert --to md` evaluated output, rendered as a plain Hugo markdown page.
5. **URL structure**: `/docs/examples/<name>/full/` as a subpage of the walkthrough.
6. **Link placement**: Top of the parent example page, prominent link/button.
7. **Sidebar**: Full-doc pages excluded from sidebar nav.
8. **Generated files**: Written to `site/content/docs/examples/<name>/full.md` with auto-generated frontmatter (title, weight, hidden-from-sidebar flag).

## Implementation Sketch

### doceval Changes

1. Parse `calcmark_source` from example page frontmatter.
2. For each page with a `calcmark_source`:
   - Read the `.cm` file from the repo root.
   - Shell out to `cm convert --to md` (or use the interpreter library directly).
   - Wrap the output with Hugo frontmatter:
     ```yaml
     ---
     title: "Services P&L -- Full Document"
     # generated by doceval -- do not edit
     ---
     ```
   - Write to `site/content/docs/examples/<name>/full.md`.
3. Add generated paths to `.gitignore` or track them (TBD during planning).

### Hugo Archetype (`site/archetypes/worked-example.md`)

The archetype enforces the required structure for worked example pages. All fields below the `---` are required; `hugo new` scaffolds them with placeholder values.

```yaml
---
title: "{{ replace .Name "-" " " | title }}"
summary: ""
weight: 0
calcmark_build: progressive
calcmark_source: "testdata/examples/{{ .Name }}.cm"
---

{{</* repo-file path="{{ .Params.calcmark_source }}" */>}}

[View full document](full/)

<!-- Walkthrough content goes here -->
```

### Hugo Layout Changes

1. Add a partial or conditional in the example page layout that reads `calcmark_source` from frontmatter and renders a "View full document" link automatically -- so authors don't need to remember to add it manually.

### Existing Example Migration

All existing example pages in `site/content/docs/examples/` will be updated to include the `calcmark_source` frontmatter field, aligning them with the archetype's required structure.

## Scope Boundaries (YAGNI)

- No custom layout/template for full-doc pages -- use standard page layout.
- No "view source" toggle -- just the evaluated output.
- No automatic table of contents generation beyond what Hugo provides by default.
- No diffing or versioning of generated pages -- regenerated fresh on each build.
